# MojiLex — описания и характеристики эмодзи

[English](README.md) | Русский

MojiLex — открытая база описаний кастомных эмодзи на **русском и английском**.
Каждая запись объясняет, что изображено, как эмодзи движется и когда его можно
использовать. Она также содержит теги и технические характеристики. Первая
поддерживаемая платформа — Telegram.

**Здесь хранятся данные.** Программа для анализа паков, просмотра результатов
и их отправки находится в репозитории
[MojiLex CLI](https://github.com/MojiLex/mojilex-cli/blob/main/README_RU.md).
Исходные файлы эмодзи, извлечённые кадры и другие бинарные медиа здесь не хранятся.

## Как выглядит запись

Этот фрагмент [полного примера](examples/telegram/emoji.json) описывает жёлтого
кота, который приподнимает бровь:

```json
{
  "descriptions": {
    "ru": {
      "text": "Жёлтый кот подозрительно приподнимает одну бровь.",
      "motion_status": "described",
      "motion": "Кот медленно поднимает бровь и замирает.",
      "usage": ["подозрение", "недоверие"]
    },
    "en": {
      "text": "A yellow cat suspiciously raises one eyebrow.",
      "motion_status": "described",
      "motion": "The cat slowly raises an eyebrow and pauses.",
      "usage": ["suspicion", "doubt"]
    }
  },
  "semantic_tags": ["cat", "doubt", "raised-eyebrow"],
  "content": {"rating": "general", "warnings": []}
}
```

Это иллюстративный фрагмент, а не полная запись, готовая к отправке. Полная
запись также содержит идентификаторы, визуальные признаки, хеши медиа, сведения
о происхождении и статус проверки. [Другие примеры](examples/README.md)
показывают видимый текст и эмодзи, которые подстраиваются под цвет текста.

Предупреждения, например `flashing` — мигающие вспышки, остаются в данных:
приложения могут показывать их или использовать для фильтрации.
**Предупреждения не требуют ручного одобрения перед публикацией.**
Необязательное ручное одобрение также не удаляет эти пометки.

## Добавить пак

Пройдите [установку CLI и обработку первого пака](https://github.com/MojiLex/mojilex-cli/blob/main/README_RU.md),
затем откройте меню:

```console
mojilex
```

Добавьте ссылку на Telegram-пак, дождитесь анализа и посмотрите описания.
Когда результат готов, выберите действие публикации. Для этого не нужно
вручную клонировать репозиторий данных или редактировать JSON.

Публикация создаёт **pull request (PR)** — предложение добавить записи.
GitHub проверяет формат и согласованность данных. В общую базу они попадут
после принятия PR. Отправка предложения и добавление записей в основную ветку —
два отдельных этапа.

Если хотите редактировать записи вручную, следуйте [CONTRIBUTING.md](CONTRIBUTING.md)
(английский).

## Использовать данные

Принятые записи доступны в [data/](data/). Чтобы приложение работало с
фиксированной версией базы, используйте конкретный Git-коммит вместо
изменяющейся ветки.

По состоянию на **13 сентября 2026 года** готовых выпусков базы для скачивания в
[GitHub Releases](https://github.com/MojiLex/mojilex/releases) нет. Можно читать
исходные JSON/JSONL-записи или [собрать и проверить снимок базы локально](docs/maintenance_RU.md).
Файлы в [examples/](examples/) — иллюстративные примеры, они не входят в
принятую базу.

| Что нужно приложению | Какие данные использовать |
|---|---|
| Подпись или текстовая альтернатива | `descriptions.ru.text` / `descriptions.en.text` |
| Движение и варианты использования | `motion_status`, `motion` и `usage` для нужного языка |
| Категории и визуальные характеристики | `semantic_tags` и `facets` |
| Пометки о содержимом | `content.rating` и `content.warnings` |
| Идентификатор на платформе и состав пака | Идентификаторы эмодзи, `extensions.telegram` и записи membership |

[Описание формата](FORMAT.md) объясняет поля, структуру каталогов и связи
записей; [JSON-схемы](schemas/v1/) задают точный контракт (английский).
Команда CLI `show` читает ваши локально проанализированные паки. Это не просмотр
всех паков из данного репозитория.

## Участие в проекте и обслуживание базы

- [Правила участия](CONTRIBUTING.md) — редактирование записей и создание PR (английский).
- [Инструкция по обслуживанию](docs/maintenance_RU.md) — локальная проверка, тесты и воспроизводимые снимки базы.
- [Подготовка релизов](docs/RELEASE_STAGING.md) — что дают артефакты CI до появления официальных выпусков (английский).
- [Сообщения об уязвимостях](SECURITY.md) и [запросы на удаление](TAKEDOWN.md) (английский).

Вклад в базу состоит только из текстовых метаданных. Не добавляйте скачанные
медиа, ключи доступа, временные ссылки скачивания или персональные данные.
Проверка репозитория работает офлайн: она не обращается к Telegram,
AI-провайдеру или ссылкам из записей.
